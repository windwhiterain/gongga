# 方向键只归光标，修饰键不算数

日期：2026-11-03

## 症状

用户报：TUI 的 cmd_input 里 `→` 移动光标失效，`←` 卡顿，`↑`/`↓` 光标皆失效。

三个症状的组合很具体：`→` 完全没反应、`←` 不按预期走、`↑↓` 光标不动。这三件事凑在一起，
只有一个原因能同时解释——**方向键带着 Alt 到达了进程**：

- `Alt+←` 是「按词跳」（`word_left`），光标一下跳几个字符，看着像卡住；
- `Alt+→` **根本没有绑定**，`Alt` 分支把它吃掉，光标一动不动；
- `Alt+↑↓` 是翻页，日志翻走了，光标当然不动。

所以「`→` 死、`←` 跳、`↑↓` 滚日志」不是三个毛病，是一个修饰键。

## 改法

方向键在 `Tui::handle_arrow` 里回答，位置在 Alt 分支和 Ctrl 分支**之前**：

- **除了 SPEC 的 `Shift+↑/↓`，方向键不看任何修饰键**。宿主给方向键加 Alt 或 Ctrl
  （键盘的 Fn 层、输入法、终端自己加的）都不能把光标抢走。
- `←→` 无论带什么修饰键都只走一格。
- 按词跳挪到 `Ctrl+←/→`（别的编辑器都放这儿）。VS Code 的终端会吃掉 Ctrl+方向键，
  那边就没有按词跳，光标照走——按不出来的绑定等于没有绑定，这仓库的老规矩。
- `Alt+↑↓` 的翻页删掉：翻页回到 SPEC 写的 `PgUp/PgDn`，滚轮也在。

## 验证

`scripts/tui_live.py` 驱动真 ConPTY（VS Code 的终端也是 ConPTY），看帧里的光标列。
输入 `one two three`（前缀两列，光标在 16 列）：

| 键 | 光标列 | 含义 |
| --- | --- | --- |
| `←` | 15 | 一格 |
| `Alt+←` | 14 | 一格（改之前是 11，按词跳） |
| `Ctrl+←` | 11 | 按词跳 |
| `Alt+→` | 12 | 一格（改之前没有反应） |
| `→` | 13 | 一格 |
| `Ctrl+→` | 16 | 词尾 |
| `Shift+↑` | — | 历史为空，没有可取回的 |
| `↑` | — | 单行输入框没有上一行 |

改之前同一张表里 `Alt+←` 是 11、`Alt+→` 没有反应——那就是用户看到的那张表。

## 没做的

- 单行输入框里的 `↑↓` 仍然什么都不做：那是输入框自己的上一行/下一行（SPEC 把「上一条命令」
  放在 `Shift+↑`）。这是设计，不是这次改坏的。
- 没给按词跳找 Ctrl 以外的家：Ctrl 是别的编辑器的位置，VS Code 吃掉它就让它没有。
  真要按词跳又不被抢，可以另编一个和弦（比如 `Alt+Shift+←`），那是另一个决定。
- 没动 SPEC：SPEC 的 hot-key 里本来就没有 Alt+方向键，删掉的不是它写下的东西。
