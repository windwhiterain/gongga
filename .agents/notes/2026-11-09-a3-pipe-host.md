## Step 7: bundle payload

`crates/bundle/build.rs` now builds `-p gongga-client` and embeds four binaries
(server, tui, client, runner). `payload_impl.rs::running_in` counts a running
`gongga-client` when deciding whether an old build's directory is still in use.
`gongga-client` is deliberately absent from `WORDS` / `by_file_name`: it is not a
program a person types. Verified with `cargo check -p gongga-bundle` (payload is
its default feature): the generated `embedded.rs` names all four and all four
binaries exist under `target/bundle-payload/debug`.

## A-3: the pipe host

`crates/tui/src/pipe.rs` is new. `gongga_tui::main` now defaults to
`pipe::run(&args)`; `GONGGA_TUI_IN_PROCESS=1` still reaches the old
`interactive()` for comparison.

- Spawns `gongga-client` beside its own executable, passes the connection flags
  and `--parent <ui pid>`, pipes stdin/stdout, and sends stderr to
  `<client-home>/client.log`.
- One task owns stdout and pushes decoded `RenderMessage`s into an unbounded
  channel. The loop `select!`s over keyboard, frames and `closing::asked()`.
  EOF on stdin is the UI leaving; ended stdout is the client leaving.
- `run.rs::apply_frame` turns the 12 drawing frames back into `Sink` calls on
  the existing `TuiSink`; the 6 control frames land on view state.
- `encode_intent` was added to `render_wire.rs` with a round-trip test.
- `Tui::for_pipe` uses an empty `Completer` and `Panes::new()` (no `Cache`);
  `set_layout` skips `Roster::know`; `Panes::keep_bodies()` disables eviction,
  because a UI with no journal cannot read cold bodies back.
- `Screen::server_text` carries the label the client spelled; `draw_header`
  prefers it over the local `Server` value.

## Decisions worth keeping

- **completion stays client-side.** A changed input line sends
  `UiIntent::Complete`; the client answers `Completion`. The UI never holds a
  catalog, and `Vocabulary` triggers exactly one re-request.
- **No second state machine.** The UI keeps only what it draws. Stamps, floors,
  the roster and the disk journal are the client's; `rewind` / `older` / `landed`
  never cross the pipe, so the TUI does not need them.
- **The fallback is temporary.** Once shape 2 settles, delete
  `GONGGA_TUI_IN_PROCESS` and `Tui`'s `Frontend` / `WindowFacts` / `WindowView`
  impls. Documented in `DESIGN.md` and `tui-pipe.md`.
