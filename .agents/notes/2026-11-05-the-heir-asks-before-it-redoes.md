# The heir asks before it redoes

The heir that inherited a session had everything the previous agent had learned — and spent a third of a context window rediscovering it anyway. It re-measured Windows console behaviour the mentor had already measured, then asked the mentor for a decision the mentor had already made. The prompt was the cause: it told the heir to read the mentor and to ask only "when you need a judgement", and it spelled the two commands as `harness {command: ...}`, a syntax this harness does not have. An agent following it literally had to work out how to reach the mentor at all.

Both spellings were wrong in ways that cost a turn. `gongga-cli send_message <session> "…"` reads the session name as the message, because the command's positional argument is the message; the working form is `--message "…" --name <session>`. The context notice's handover command still carried `--session {{session}}`, which `heir` removed when it began taking the caller from `$GONGGA_SESSION`: the notice told the agent to run a command that exits with "unrecognized arguments" at the exact moment it was told to run it.

The rules now: the injected guidance names commands that work, `gongga-cli get_messages --session <mentor> 1:` to read and `gongga-cli send_message --message "<question>" --name <mentor>` to ask, and the rule is to ask before redoing rather than only when a judgement is needed — one question is a turn, a repeated search is the whole search again. The mentor's own injected text names the same commands, because the answer has to reach the heir's session as a message and the mentor is the one who sends it. The notice's command lost both `--session` and `--mentor`: the script derives the caller from the environment and already picks a free name under the session's own path.

Validation: `scripts/heir_selftest.sh` passed against the current server schema, and every command line in the injected text was extracted and run against the live server — four of four accepted. The change is content, so it published through `scripts/ship.sh` without touching the protocol; a running server installs it at its next start.
