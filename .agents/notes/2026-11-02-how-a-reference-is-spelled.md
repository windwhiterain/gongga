# `@` 引用的检测规则：谁教它、多严、错了会怎样

User：「heir 的 prompt 里提示了要用 @... 的形式引用吗？以及目前的 @... 检测规则会不会太严格导致 AI 写错？」

## 谁教它

**没有任何 prompt 教。** 逐处查过：

| 位置 | 有没有提 `@` |
| --- | --- |
| `instructions`（系统散文） | 没有 |
| `context_notice`（让它跑 `heir` 的那条） | 没有，只给 `--note '...'` |
| `reference_index` 模板 | 只说「一个只有引用的行，后面是它代表的文本」，不教拼法 |
| `index_skill` 工具描述 | 本地会话里没有（只有远端会话的附注提到 `@skill:`） |
| `image` skill | 教 `@image:`（含「值必须是一个词」） |
| `heir` skill | 只在「为什么走 send_message」那段提到 `@file:`/`@skill:` |
| TUI 输入补全 | 给**人**用的，模型看不到 |

唯一的「教学」是**示例**：只要会话目录有 `AGENTS.md`，第一次请求的 index 里就有
`@file:AGENTS.md` 加它的正文；模型能从这儿反推拼法。目录里没有 `AGENTS.md`
且消息里也没引用时，index 为 `null`，模型什么都看不到。

## 多严（实测）

`bash .dev/meta-probe/probe.sh`：一个临时 home、一个 fake endpoint、一条首轮消息，
26 种拼法各指一个**自己的**文件/技能（每个变体一个文件，否则同一拼法会按 spelling
去重，把「有没有被认出来」藏掉）。

认得出（12 个 spelling）：

| 写法 | 结果 |
| --- | --- |
| `@file:v01.md` | 认，正文进 index |
| `@file: v02.md`（空格式） | 认 |
| `@file:./v03.md`、绝对路径 | 认（各自一条 index，同一文件多份副本） |
| `(see @file:v10.md).`、`` `@file:v11.md` ``、`@file:v12.md;`、`` "`@file:v24.md`" `` | 认（前后 ASCII 引号/括号/反引号被剥掉） |
| `@file: v14.md and more` | 认，只取第一个词 |
| `@file:v16`（无扩展名） | 认 |
| `@skill: s18`、`@skill:s19` | 认，正文进 index |

认不出（全部**静默**：文本原样留着，index 没有内容，没有报错、没有事件��模型也不知道）：

| 写法 | 为什么 |
| --- | --- |
| `@File:v05.md` | 前缀大小写敏感 |
| `@file:v06.md，然后继续` / `@file:v07.md。然后继续` | 值是一整词，`，`/`。` 后面没有空格，所以值变成 `v06.md，然后继续`；尾部 trim 只剥 ASCII，中文标点不在里面 |
| `@skill:s20，然后` | 同上：技能名变成 `s20，然后`，查不到 |
| `「@file:v08.md」` / `“@file:v09.md”` | 前导 trim 只有 ASCII `([{"'\`` |
| `@v13.md` | 裸 `@` 不是引用 |
| `@file:dir with space/v25.md` | 只取 `dir` → 读不到；`@file:` 值必须是一个词（`image` skill 里写了这条，但只在那种情境下读得到） |
| `@file: "dir with space/v25.md"`、`@file:dir\ with\ space/...` | 同上，引号和反斜杠都不救 |
| `[x](@file:v17.md)` | 词首是 `[`→`x`，前缀对不上 |
| `@ file:v21.md`、`@file :v22.md`、`@@file:v23.md` | 都不是 `@kind:` 开头 |

## 结论

- 对**英文**写法够宽松（括号、反引号、分号、句号都能剥掉）。
- 对**中文**写法是最坏的一档：中文句子里引用后面不打空格，直接接 `，` `。`，
  就整段失效；而且失效是静默的——继承人的第一课里会留一句「读 @file:plan.md」，
  实际什么都没进 index，继承人要么自己再读一遍文件，要么根本没意识到该读。
- 反过来也有一点「太松」：反引号里的示例也会被当真（文档里写 `` `@image: x` ``
  会真的去上传）。在用户消息里这是false positive 的来源，在 index 的递归 walk 里
  则无所谓（`@image:` 读不到内容就跳过）。

## 可选改法（未做，等 user 定）

A. **读不到就退一步**：拼法照旧严格解析，只在**读不出文件/查不到技能**时，把值在
   第一个终止符处截断再试一次（`，；：！？、）」』””》〉` 以及 `,;!?`）。先试原值，
   所以对含这些字符的真实文件名零风险；修的正是中文标点粘连。≈15 行，一处。
B. **前缀大小写不敏感**（`@File:`）。一行。
C. **路径含空格**：值取到行尾，最长前缀匹配到真实存在的文件为止。要一次 fs 探测，
   且会吞掉后面的正常文字——只在「整段读不到」时才可以试。
D. **失败要出声**：某个 mention 读不到时给会话一条 `notice`。把 silent failure
   变成信息，但要定义「什么算想写引用」，`@types/node` 这类会误报。
E. **写进散文**：`heir` skill 或 `context_notice` 里加一句「文件和技能用
   `@file: <一个词>` / `@skill: <名字>` 引用」。最便宜，但要花每个会话前缀的 token。
