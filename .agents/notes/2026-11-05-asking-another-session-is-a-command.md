# Asking another session is a command

The heir had been told to ask its mentor with the command layer's raw `send_message`, and it kept not asking: the message and the session name sit in the same call, and the positional order is the message first. `send_message shell/mentor "…"` therefore reads the session name as the question, and the question as a session that does not exist — an error that reads like a typo rather than a trap. The heir then re-derived what the mentor already knew.

So asking became one command with the arguments in the order that cannot be confused: `ask_session <session> "<question>"`. It lives in the `self-control` skill, next to the four levers a caller already reads, and it is that skill's entry, so `gongga-cli skill self-control <session> "<question>"` reaches it with the arguments passed through. It does two things in one step: the question goes to the session the way `send_message` does, and the answer is waited for and printed.

The answer is not a re-ask of the session's transcript. It is the transcript itself: the turn that answered ends there, and its own words are the answer. The cursor is taken before the question is sent, so a turn that ended before the question cannot be mistaken for the answer. The server's `status` says whether that session is still running, which is what tells the reader the turn is over rather than half-written. A message the session sends elsewhere is a second copy, not the record: the mentor's injected duty now says to put the whole answer in its own turn as well, because a message alone leaves the reader with the sender's receipt.

Two shapes of the same mistake were fixed together. The heir's injected text named `harness {command: …}`, a syntax this harness does not have, so an agent following it literally had to work out how to reach the mentor at all; it now names commands that run. And the context notice told the agent to run `transcript heir --session {{session}} …`, a flag `heir` removed when it began taking the caller from `$GONGGA_SESSION`: the notice taught a command that exits with "unrecognized arguments" at the moment it was told to run it.

Validation: `scripts/heir_selftest.sh` passed against the current server schema, `scripts/skill_contract.sh` passed, and every command line in the injected text was extracted and run against the live server — four of four accepted, including the new `skill self-control …` form, which waited for the mentor's answer and printed it. The change is content, so it published through `scripts/ship.sh` without touching the protocol; a running server installs it at its next start.
