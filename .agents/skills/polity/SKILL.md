# polity：三个角色，一套档案

"多叫几个 agent 并行干活"本身不解决任何问题——它只让产出变多，不解决**谁来判断做对了**。
这个 skill 的重点是把裁判和选手分开：

> 写宪法的人不写代码；写代码的人不判自己。

这不是道德要求。**只要一个人既做又判，合宪就只是一句自我声明**——判决里就没有信息量了。
所有形态上的规矩（谁碰宪法、谁能派生、判决要不要证据）都是从这一条推出来的。

---

## 1. 三个角色

| 角色 | 一句话 | 碰宪法 | 产出 |
|---|---|---|---|
| **大法官** | 与 user 对话，把意图写成宪法，向别人解释宪法，只读总理的汇报判合宪性 | **只有他**能改 | `constitution.md`、`rulings/` |
| **总理** | 拆任务、派工、收结果、review、跑测试、取证，向大法官汇报 | 不能 | `tasks/`、`proposals/`、`reports/` |
| **执行者** | 只做被派的那一件事，给证据 | 不能 | `reports/<任务>.md` |

几件"不做"的，比"做"重要：

- 大法官**不写实现、不派工、不跑测试、不取证、不读代码下判断**。他只读总理的汇报；
  证据由他点名要，不由他去取。一动手就失去了判自己的资格。
- 总理**不改宪法、不判自己合宪**，也不在判决回来前做"可能违宪"的那部分。
- 执行者**不派生 agent、不和 user 对话**。

## 2. 真机制（都实测过，不是设计愿景）

```bash
P=.agents/skills/polity/polity
```

| 事实 | 数字 / 说明 |
|---|---|
| `send_message` 立刻返回 | 实测 **0.25 秒**；回合在后台跑 |
| 会话忙时再发消息 | **注入正在跑的那个回合**，不是排队 |
| `set_session` 同名再调 | 幂等；返回里带**所有会话的 status**，是 CLI 里唯一的只读状态来源 |
| `get_messages --seq <a>:<b>` | 行区间（1 基、两端含、`-5:` 取最后五条）+ `last_seq`，可反复轮询 |
| per-session 系统提示 | **没有**。`instructions` 只有全局一份 |
| 子会话的 `$GONGGA_CLI` | 有。所以总理能再派生执行者——两层是真的 |

两个直接后果：

1. **角色只能靠消息和文件承载。** 没有 per-session 系统提示，所以 `dispatch` 每次都把
   角色、宪法路径、章程路径、铁律重新写进派工消息里。不要指望"创建时设过一次"。
2. **派工 ≠ 做完。** 派完必须 `wait`。

## 3. 为什么要 seq 基线（最容易写错的一处）

`wait` 要两件事**同时**成立：

- 会话 `status` 是 `idle`；
- **派工前记下的 seq 之后**，出现了新的助手正文。

只满足前者，会立刻返回上一轮的答案（"idle" 也是上一轮留下的状态）；只满足后者，会拿到
一个还在跑的回合的半截回复。所以基线必须在**发消息之前**取——`dispatch` 就是先取基线再发，
它会把基线打印给你，照抄进 `wait --after`。

```bash
$P dispatch --to w1 --task 001 --title "…" --body @-   # 打印 基线 seq = 42
$P wait --session w1 --after 42 --timeout 600
```

`wait` 的退出码：`0` 拿到收尾正文；`3` 超时；`5` 回合结束了但没有收尾正文（通常是跑崩了）。
`5` 和 `3` 都要看 `read`，别当成功。

## 4. 一次完整的闭环

档案都在 `.polity/` 下，`init` 会建好：`constitution.md`、`charter/`（三份职责）、
`templates/`（四份模板）、`tasks/`、`proposals/`、`rulings/`、`reports/`、`ledger.jsonl`。

**报告一律叫 `reports/<任务>.md`**，没有角色后缀——任务号本身就是作者唯一的（大法官派 001，
总理派 001a），所以不需要再区分。这个约定只写在 `polity.py` 的 `report_path()` 一处，派工消息、
任务单和模板都指向它。最初我写成了「派工消息说 `<任务>.<角色>.md`、任务单说 `<任务>.md`」，
**两个 agent 各自独立地撞上了这个矛盾并同时上报**——这也是把它们留在档案里而不是口头说清的原因。

### 大法官（= 正在和 user 说话的这个会话）

```bash
$P init                      # .polity/、宪法骨架、三份章程
$P up --pm pm                # 开总理会话
# 手写 .polity/constitution.md：把 user 的原话变成条款
$P dispatch --to pm --task 001 --title "把 A 的构建搬到 B" --role pm --body @-
$P wait --session pm --after <上面打印的基线> --timeout 900
$P read --session pm --after 0         # 读总理的汇报：做了什么、拿了什么证据
$P new ruling 001                      # 判；证据不回答问题的，退回，不判
```

### 总理（被派工的那个会话）

```bash
$P dispatch --to w1 --task 001a --title "改 a.txt" --role worker --body @-
$P wait --session w1 --after <上面打印的基线> --timeout 600
$P verify --root .                     # 取证：git 上到底改了什么（输出贴进汇报）
$P new report 001                      # 汇总，交给大法官
$P send --session <大法官的会话> --tag 汇报 --message "001 汇报已就绪：.polity/reports/001.md"
```

### 执行者

读任务单 → 干活 → 复制 `.polity/templates/report.md` 到 `.polity/reports/<任务>.md` 并填 →
最后只回 `DONE <任务号>`。不要复述全文：原文在文件里，谁要谁读。

模板是**文件**，不是"去 `polity.py` 里找"。早先只有代码里的字典，结果执行者为了不违反
"只写一份文件"的约束，去读了源码抄字段——这不该发生。

## 5. 宪法怎么写

一条一个约束，句式必须**能判真假**：

```
## 第三条 不许动发布分支
- 条文：不得对 main 直接 push；只能通过 PR 合入。
- 出处：user「（原话）」2026-…-…
- 判据：git log --first-parent main 上出现任何非 merge 提交即违反。
```

- 反例：「注意安全」「保持优雅」「代码要清晰」——这些判不了，不是条款。
- 每条都要有**出处**（user 的原话，加引号）和**判据**（怎么看算违反）。
- 拿不准的边界，先向 user 复述一遍再写：猜出来的约束不要写成条款。
- 只有大法官能改；每次改在文末留一行修订记录（版本、日期、为什么、改了什么）。

文件位置：`.polity/constitution.md`，模板由 `polity init` 生成。

## 6. 判决

三种结果，必须选一个：

| 结论 | 意思 |
|---|---|
| **合宪** | 可以继续 |
| **违宪** | 停。指出违反第几条，要求重做；已落地的实现要回退 |
| **有条件合宪** | 可以做，但先满足条件；下次判决逐条核 |

两条硬规矩：

1. **判决必须引用条款号。** 指不出第几条，就不是判决，是意见。
2. **判决只吃点名要来的证据，不自己取。** 总理说"已完成、测试通过"不构成证据；
   你要点名：哪条命令及其输出、哪个路径、哪个 diff、要看到什么结果。`polity verify`
   的 git 事实（`status` / `diff --stat` / `log`）由总理跑、总理贴，你判它回不回答问题。
   读代码、跑命令都不该发生在你手里——**要证据不是取证**。汇报只有结论没有证据，
   原样退回，不判。判决模板里"证据"那一栏写着"不接受自述"，就是为这个。

**盯证据质量：`verify` 的盲区。** 如果 root 本身被外层仓库的 `.gitignore` 忽略，
`git status` 会是空的——那不是"没改动"，是"这个目录不归 git 管"。`verify` 遇到这种情况
会打警告；汇报若拿这种空输出当证据，退回，点名要 mtime / md5。demo 里的总理撞上过这一条
（`.dev/` 被忽略），并且自己换了证据方式。

## 7. 档案的格式

`polity new task|proposal|ruling|report <号>` 生成模板，字段缺一不可：

- **任务单**：标题 / 交给谁 / 输入 / 交付物 / 完成判据 / 禁止。
  完成判据要是一条能跑的命令或一个能看的状态，不是"做好了"。
- **提案**：一句话 / 服务哪几条宪法 / 会碰到什么 / 可能违反哪条 / 怎么验证 / 预算。
  "可能违反哪条"哪怕自陈"看不出"也要写——这是给大法官的输入。
- **判决**：见上。
- **汇报**：做了什么 / 与提案的偏差 / 证据 / 没做完的为什么 / 要裁决什么。**短**。

档案都不覆盖写：任务号已经被用过，`dispatch` 会用盘上那一份并警告；判决和汇报同理。
一个会静默丢判决的档案库比没有更糟。

**章程和模板也是从不覆盖的副本**，所以器具改了法、旧法庭还在读旧章程——这正是
`polity status` 现在会逐条警告的东西：哪一份、从第几行开始不同、盘上与内置的两个 md5。
只提醒，不改退出码、不挡任何命令：副本不是法，法在宪法，副本与法不一致时副本错。看到警告
就按内置文本对齐，或删掉那份文件重新 `polity init`（`init` 只补缺的）。

## 8. 反模式

| 反模式 | 后果 |
|---|---|
| 大法官顺手改一行代码 | 它再判这段就是判自己，制衡消失 |
| 收"已完成、测试通过"就判合宪 | 判决退化成转述 |
| 大法官自己跑 `verify`、读代码取证 | 既做又判，判决还是自我声明；证据该点名要，不该自己取 |
| 一个会话里轮流演三个角色 | 制衡消失，退化成普通对话——那就别用这个 skill |
| 把 CLI 原始输出贴进上下文 | 会自我递归膨胀（实测一条命令 16 KB） |
| 一次开十个会话 | 并行度有上限：`.polity/state.json` 的 `max_parallel`（默认 3），超了先等 |
| worker 再派 worker | 只有总理能开人；否则没人知道总共有几个在跑 |
| 用 status 判断做完 | 见第 3 节：idle 可能是上一轮的 |

## 9. 收尸

```bash
$GONGGA_CLI interrupt_session --session w1   # 停它的回合，回合被丢弃
$GONGGA_CLI del_session --session w1         # 连 transcript 一起删
```

detached 的进程不随会话死（见 `self-control`）。判决"违宪、要回退"时，先停会话再回滚文件，
否则它可能一边被你回滚一边继续写。

## 10. 脚本和测试

```bash
.agents/skills/polity/polity --help          # 10 个子命令
.agents/skills/polity/polity status --root .
python3 .agents/skills/polity/test_polity.py # 116 项，退出码即结论
```

`test_polity.py` 分两层：`wait_loop` 对着**脚本化的时钟**跑（时序错误都在那里），
其余对着 `fake_cli.py` 起**真子进程**跑（一次命令一个进程，跟真客户端一样）。
十四项变异验过：去掉 idle 条件、去掉新回复条件、基线改到发之后、档案允许覆盖、不挡 JSON
标量行、派工失败当成功、不报已消失的会话、角色一律写成大法官、报告名带回角色后缀、init 不落模板、
verify 不警告被忽略的根、任务单不带交付章节、任务单不填标题和作者、吞掉客户端的 stderr——
每一项都有测试变红。
2026-10-24 新法（`SPEC.md` §Polity）落地时补了四条断言——法官「要证据不是取证」、
法官「不跑测试/不取证」、总理「review/跑测试/取证」、判决模板「退回不判」——
每条各做一次变异，全红。
003 又补十三条——`brief()` 的铁律 2 按角色分叉（总理那份不得再出现「不得派生」，且要报并行度；
执行者那份不得松动）、`status` 的章程漂移警告（真漂移要报、全新法庭不许报、退出码不变、
缺文件也要报）、`verify` 的帮助不再写「独立取证」——四条变异各红一次。

测试自己的教训也记在这里：最初"未跳过非 JSON 行"和"角色一律大法官"这两个变异**没红**——
前者因为 try/except 本来就挡住了非 JSON（那个判断真正挡的是 `42` 这种**合法 JSON 但不是对象**
的行，会让下游 `.get` 崩），后者因为断言用的"总理"二字被铁律里"向总理申请"那句满足了。
补了 JSON 标量行和 `【角色】总理` 精确断言之后才抓住。

不需要改 Rust：加 skill 只建目录。

**跑测试时当心的一个坑：** `polity.py` 用 `$GONGGA_CLI` 找客户端，而 `default` shell 是持久的。
一旦为了试验 `export GONGGA_CLI=<假客户端>`，**这条 shell 后面每一条 CLI 调用都是假的**——
我这么干过，然后回头"确认会话状态"时拿到的是假客户端的回答（`llm fake/model`），
差点据此下结论。试完立刻恢复，或者干脆用 `env GONGGA_CLI=… polity …` 只影响那一条命令。
